# منصة انخراط الحكام — الرابطة الولائية لكرة القدم الوادي

منصة ويب كاملة (خادوم Node.js + واجهة أمامية) لإدارة انخراط الحكام:
إنشاء حساب، تعبئة الاستمارة، رفع الوثائق، مراجعة الإدارة (قبول/رفض مع
ملاحظات على كل حقل ووثيقة على حدة، مع إمكانية مراجعة كل وثيقة بحجم كبير قبل
اتخاذ القرار)، وإصدار وثيقة الانخراط الرسمية تلقائيًا عند الموافقة.
**الانخراط مجاني بالكامل — لا توجد أي مرحلة دفع في المنصة.**

## البيانات محفوظة بشكل دائم وحقيقي (وليس على القرص المحلي)

- **قاعدة البيانات**: MongoDB Atlas (سحابية، مجانية للأبد، حفظ دائم حقيقي).
- **الوثائق المرفوعة**: Cloudinary (تخزين ملفات سحابي، مجاني، حفظ دائم حقيقي).

هذا يعني أن المنصة يمكن نشرها على استضافة مجانية بقرص غير دائم (مثل Render
المجانية) دون أن تفقد أي بيانات — راجع القسم 3 لشرح إعداد الحسابين المجانيين
خطوة بخطوة.

## قبل الموافقة: تعديل حر — بعد الموافقة: تعديل عبر طلب

- ما دام ملف الحكم **مسودة، أو قيد المراجعة، أو مرفوضًا**، يمكنه تعديل أي
  معلومة أو وثيقة بحرية من صفحة "تعديل الاستمارة".
- بمجرد **قبول** الملف وصدور وثيقة الانخراط، يتوقف التعديل المباشر، ويحصل
  الحكم بدلًا من ذلك على:
  - **ملفه الشخصي الكامل** — عرض كل بياناته ووثائقه في أي وقت.
  - **طلب غياب** (مع إمكانية إرفاق تبرير كصورة أو PDF) — يرسله للإدارة.
  - **طلب خاص** — نص حر موجَّه للإدارة تقبله أو ترفضه.
  - **طلب تعديل معلومة** — يختار الحقل والقيمة الجديدة والسبب؛ إن وافقت
    الإدارة، يُطبَّق التعديل تلقائيًا في ملفه.
- الحكم يمكنه **تعديل** أي طلب من طلباته ما دام **قيد الانتظار**، أو **بعد
  رفضه** (لتصحيحه وإعادة إرساله تلقائيًا). لا يمكن تعديل طلب تمت الموافقة
  عليه. كما يمكنه **حذف** أي طلب **قيد الانتظار فقط** — لا يمكن حذف طلب تم
  قبوله أو رفضه.

## صلاحيات الإدارة الكاملة

- معاينة وثيقة الانخراط الصادرة لأي حكم، والتراجع عن قبول ملف سبق قبوله
  (تُلغى الوثيقة ويعود الملف لقائمة المراجعة).
- **تعديل مباشر وكامل** لأي معلومة في ملف أي حكم (بغض النظر عن حالته)، من
  زر "✎ تعديل معلومات الحكم" داخل صفحة مراجعة الملف.
- **حذف حكم بالكامل** (الحساب + الملف + كل الوثائق المرفوعة على Cloudinary +
  كل طلباته) من صفحة "كل الحسابات المسجَّلة" — إجراء نهائي لا يمكن التراجع عنه.
- صفحة مخصصة "طلبات الحكام" للبت في طلبات الغياب والطلبات الخاصة وطلبات
  تعديل المعلومات، مع إمكانية **تغيير القرار لاحقًا** (قبول ↔ رفض ↔ إعادة
  لقيد الانتظار) و**تعديل محتوى الطلب** مباشرة قبل البت فيه.

على عكس النسخة الأولى (ملف HTML واحد يعمل محليًا في المتصفح)، هذه النسخة
خادوم حقيقي: البيانات محفوظة على الخادوم وليس في متصفح كل جهاز — أي أن حساب
الحكم الذي يُنشأ من هاتفه سيظهر مباشرة عند الأدمن على حاسوبه، وأي جهاز يتصل
بنفس الرابط يرى نفس البيانات.

## 1) المتطلبات

- تثبيت **Node.js** (نسخة 18 أو أحدث). حمّله من: https://nodejs.org
- حساب **MongoDB Atlas** مجاني (لقاعدة البيانات) — شرح الإنشاء في القسم 3.
- حساب **Cloudinary** مجاني (لتخزين الوثائق المرفوعة) — شرح الإنشاء في القسم 3.

## 2) التشغيل محليًا (على جهازك)

بعد إنشاء الحسابين وملء ملف `.env` (القسم 3)، افتح الطرفية داخل مجلد
المشروع ثم نفّذ:

```bash
npm install
npm start
```

بعدها افتح المتصفح على:

```
http://localhost:4000
```

## 3) إعداد قاعدة البيانات والتخزين (مرة واحدة فقط)

### أ) إنشاء قاعدة بيانات MongoDB Atlas المجانية

1. اذهب إلى https://www.mongodb.com/cloud/atlas/register وأنشئ حسابًا مجانيًا.
2. عند سؤالك عن نوع القاعدة، اختر الخطة المجانية **M0 (Free)**.
3. اختر أي مزوّد ومنطقة قريبة (مثلًا AWS – Frankfurt أو Paris)، ثم أنشئ العنقود (Cluster) — يستغرق بضع دقائق.
4. من "Database Access" أنشئ مستخدم قاعدة بيانات (اسم مستخدم وكلمة مرور، احتفظ بهما).
5. من "Network Access" أضف عنوان IP: اختر "Allow Access from Anywhere" (0.0.0.0/0) حتى يعمل من أي استضافة.
6. من "Database" اضغط "Connect" ثم "Drivers"، وانسخ رابط الاتصال (Connection String)، شكله:
   ```
   mongodb+srv://USERNAME:PASSWORD@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```
7. استبدل `USERNAME` و`PASSWORD` ببيانات المستخدم الذي أنشأته في الخطوة 4.

### ب) إنشاء تخزين Cloudinary المجاني

1. اذهب إلى https://cloudinary.com/users/register/free وأنشئ حسابًا مجانيًا.
2. بعد الدخول للوحة التحكم (Dashboard)، ستجد مباشرة:
   - **Cloud Name**
   - **API Key**
   - **API Secret** (اضغط "Reveal" لإظهارها)
3. انسخ القيم الثلاث.

### ج) وضع البيانات في ملف `.env`

أنشئ ملفًا باسم `.env` في جذر المشروع (بجانب `package.json`) بالمحتوى التالي، مع استبدال القيم بما نسخته أعلاه:

```
PORT=4000
JWT_SECRET=غيّر-هذا-النص-إلى-قيمة-عشوائية-طويلة-وسرية
ADMIN_USERNAME=admin
ADMIN_PASSWORD=كلمة-مرور-قوية-من-اختيارك

MONGODB_URI=mongodb+srv://USERNAME:PASSWORD@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority

CLOUDINARY_CLOUD_NAME=your-cloud-name
CLOUDINARY_API_KEY=your-api-key
CLOUDINARY_API_SECRET=your-api-secret
```

بعدها نفّذ `npm start` — إن ظهرت رسالة "✔ تم الاتصال بقاعدة البيانات بنجاح" فالإعداد سليم.

## 4) حساب الإدارة الافتراضي

يُنشأ تلقائيًا عند أول تشغيل (بعد نجاح الاتصال بقاعدة البيانات):

- **اسم المستخدم:** `admin`
- **كلمة المرور:** `LWF@2026` (أو القيمة التي وضعتها في `ADMIN_PASSWORD`)

## 5) تغيير كلمة السر (للإدارة أو للحكم، من داخل المنصة)

أي مستخدم مسجَّل الدخول يمكنه تغيير كلمة سره بنفسه في أي وقت من زر
**"⚙ حسابي"** أعلى الصفحة.

## 6) نسيت كلمة سر الإدارة؟

نفّذ من داخل مجلد المشروع (يتطلب أن يكون ملف `.env` معدًّا بشكل صحيح):

```bash
npm run reset-admin
```

أو بكلمة سر من اختيارك:

```bash
npm run reset-admin -- "كلمة-سري-الجديدة"
```

## 7) بنية المشروع

```
lwf-server/
  server.js               نقطة انطلاق الخادوم (يتصل بقاعدة البيانات أولاً)
  db.js                    طبقة قاعدة البيانات (MongoDB Atlas)
  cloudinary.js            طبقة تخزين الوثائق المرفوعة (Cloudinary)
  schema.js                تعريف حقول الاستمارة والوثائق المطلوبة
  config.js                الإعدادات (تُقرأ من ملف .env)
  middleware/auth.js        التحقق من تسجيل الدخول والصلاحيات
  routes/auth.js            تسجيل الدخول / إنشاء حساب / تغيير كلمة السر
  routes/applications.js    مسارات الحكم: تعبئة الاستمارة، رفع الوثائق، الإرسال
  routes/admin.js           مسارات الإدارة: المراجعة، التعديل المباشر، الحذف، طلبات الحكام
  routes/requests.js        مسارات طلبات الحكام (غياب / خاص / تعديل معلومة)
  scripts/reset-admin-password.js   أداة استرجاع كلمة سر الإدارة
  public/                   الواجهة الأمامية (HTML/CSS/JS)
```

## 8) النشر على استضافة مجانية (Render)

1. أنشئ حسابًا على https://render.com (مجاني، يمكن الدخول عبر GitHub).
2. ارفع مجلد المشروع إلى مستودع GitHub (أو استخدم خيار الرفع المباشر إن توفر).
3. من لوحة Render: New → Web Service → اختر المستودع.
4. اضبط:
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
5. من قسم "Environment"، أضف كل المتغيرات الموجودة في ملف `.env` لديك محليًا
   (`MONGODB_URI`, `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`,
   `CLOUDINARY_API_SECRET`, `JWT_SECRET`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`).
6. اضغط Deploy — بما أن كل البيانات والملفات محفوظة خارجيًا (MongoDB +
   Cloudinary)، فلن تفقد أي شيء حتى مع إعادة التشغيل التلقائي للخطة المجانية.

## 8.1) منع دخول التطبيق في وضع الخمول (Keep-Alive / Cron Job)

خطة Render المجانية توقف الخدمة تلقائيًا بعد نحو 15 دقيقة بدون أي طلب HTTP
واردة، فيضطر أول زائر بعدها للانتظار 30-60 ثانية لحين إعادة التشغيل (Cold
Start). أضفنا طبقتين للتعامل مع هذا — يُفضَّل تفعيل الاثنتين معًا:

**أ) نبضة تنشيط ذاتية (مفعّلة تلقائيًا، لا تحتاج إعدادًا على Render)**

الخادم (`server.js`) يرسل طلبًا لنفسه إلى `GET /api/health` كل 10 دقائق،
اعتمادًا على متغير البيئة `RENDER_EXTERNAL_URL` الذي توفّره Render تلقائيًا
لكل خدمة ويب — أي أنها تعمل من أول نشر دون أي إعداد إضافي. **حدّها:** هذه
النبضة تمنع دخول الخدمة في وضع الخمول أصلًا، لكنها لا تستطيع "إيقاظ" خدمة
توقفت فعلًا (لأن العملية التي تُرسل النبضة تكون هي نفسها متوقفة حينها) — لذا
لا تُعتبر ضمانًا كاملًا لعمل الخدمة 24/24 بمفردها.

**ب) Cron خارجي مجاني (يُنصح به بشدة كطبقة ثانية)**

اختر أحد الخيارات التالية ووجّهه إلى:
`https://YOUR-APP-NAME.onrender.com/api/health`
كل 10-14 دقيقة (أقل من 15 دقيقة، حد الخمول عند Render):

- **cron-job.org** (مجاني بالكامل): أنشئ حسابًا → Create Cronjob → ضع
  الرابط أعلاه → اضبط التكرار كل 10 دقائق → فعّل.
- **UptimeRobot** (مجاني، ويوفر أيضًا تنبيهًا إن توقفت الخدمة فعلًا): أنشئ
  حسابًا → Add New Monitor → نوع HTTP(s) → ضع الرابط → الفاصل الزمني 10
  دقائق (الحد الأدنى في الخطة المجانية).
- **GitHub Actions** (إن كان المشروع على GitHub): أضف ملف
  `.github/workflows/keep-alive.yml` بمحتوى:
  ```yaml
  name: Keep Render app awake
  on:
    schedule:
      - cron: "*/10 * * * *"
    workflow_dispatch: {}
  jobs:
    ping:
      runs-on: ubuntu-latest
      steps:
        - run: curl -sf https://YOUR-APP-NAME.onrender.com/api/health
  ```

أي من هذه الخيارات يستدعي فقط `/api/health` (لا يتطلب تسجيل دخول ولا يقرأ
من قاعدة البيانات)، وهو نفس المسار الذي تستخدمه النبضة الذاتية الداخلية.

## 10) النظام المالي (المالية) — أصبح مشروعًا منفصلاً

كان النظام المالي وحدة داخل هذا المشروع نفسه (`/finance`)، وقد **فُصل الآن
بالكامل إلى مشروع مستقل: `lwf-finance-system`** — خادم Express منفصل،
واجهة مستقلة، ونشر منفصل — لكنه **يتشارك مع هذا المشروع نفس قاعدة بيانات
MongoDB** (نفس `MONGODB_URI`)، لذلك تبقى كل حسابات "المسؤول المالي"/"مستخدم
للعرض" وكل العمليات المالية المسجَّلة سابقًا سليمة تمامًا دون أي ترحيل يدوي
للبيانات.

**ماذا تغيّر هنا بالضبط:**
- حُذفت من هذا المشروع: `routes/finance.js`, `financeCore.js`,
  `financeExcel.js`, `financePdf.js`, `financeAuditCore.js`,
  `pdfRenderer.js`, `arabicShape.js`, `public/finance.html/.js/.css`،
  وحُذفت اعتماديتا `exceljs` و`puppeteer` من `package.json` (لم تعودا
  مُستخدَمتين هنا، مما يجعل `npm install` أسرع وأخف بكثير).
- زر "💰 النظام المالي" أُزيل بالكامل من شريط الإدارة العلوي
  (`public/app.js`) — منصة الحكام لم تعد تحتوي على أي رابط أو إشارة إلى
  النظام المالي. للوصول إلى `lwf-finance-system` بعد نشره، استخدم رابطه
  مباشرة (يمكنك مثلاً إضافته كإشارة مرجعية في متصفحك، أو إعادة إضافة رابط
  له لاحقًا إن أردت ذلك).
- `db.js` في هذا المشروع لم يعد "يعرف" حقول النظام المالي، لكنه أيضًا لا
  يحذفها أو يكتب فوقها أبدًا — أي بيانات مالية موجودة في قاعدة البيانات
  المشتركة تمر عبره سليمة دون تغيير في كل عملية قراءة/حفظ.

**ملاحظة مهمة عن تسجيل الدخول:** في النسخة القديمة (نفس الخادم)، كان
دخول المدير هنا يُدخله تلقائيًا إلى `/finance` أيضًا (لأن الصفحتين كانتا
تتشاركان نفس أصل المتصفح ونفس `localStorage`). بعد الفصل إلى مشروعين على
رابطين مختلفين، **لم يعد هذا التسجيل التلقائي ممكنًا** — على المدير/الموظف
المالي تسجيل الدخول بشكل منفصل في `lwf-finance-system`، بنفس اسم المستخدم
وكلمة السر كما كانا من قبل.

راجع ملف `README.md` داخل مشروع `lwf-finance-system` لتفاصيل تثبيته
ونشره (نفس خطوات Render/MongoDB Atlas/Cloudinary أدناه، لكن كخدمة ويب
ثانية منفصلة).

## 9) النسخ الاحتياطي

البيانات كلها الآن على MongoDB Atlas وCloudinary، لا على جهازك — لوحة تحكم
MongoDB Atlas توفر نسخًا احتياطية تلقائية (حتى في الخطة المجانية بشكل محدود)،
ويمكنك أيضًا تصدير البيانات يدويًا من لوحة Atlas عند الحاجة.
